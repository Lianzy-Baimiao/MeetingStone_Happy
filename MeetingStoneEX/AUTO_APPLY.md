# 自动申请地下城队伍

执行 `/reload` 后，在集合石「查找活动」中先选择地下城并设置搜索、过滤条件，再点击「申请加入」右侧的「自动申请」。先在备注提示中选择「带备注开始」「无备注开始」或「取消」，确认后才启动。按钮变成「停止自动申请」表示正在运行；鼠标悬停可查看当前状态。

备注窗口中可设置「最大等待时间」，输入 1–300 的整数秒，默认 300 秒（5 分钟）。例如填 `60`，表示每个自动提交的申请最多等待 1 分钟；带备注和无备注开始都会使用这一设置。

- 识别当前专精的坦克、治疗或输出职责，按五人队伍的 1 坦克、1 治疗、3 输出判断空位。
- 开始前复用游戏原有申请备注输入框（原有 63 字符限制），填写一次后本次申请沿用该备注。「无备注开始」会清空旧备注；「取消」、关闭弹窗或按 Esc 都不会启动。不会在自动刷新或补申时重复提示。
- 备注不自动保存到下次登录；再次开启时可以复用游戏输入框仍保留的文字。如果运行期间通过手动申请等方式修改了备注，自动申请会停止并提示重新确认，避免发送不同的内容。
- 使用当前完整过滤列表（包括滚动区域之外的行），按现有成员人数从多到少逐个申请。同人数按结果 ID 排序。
- 开启期间约每 7 秒自动调用原有刷新按钮的处理逻辑，并遵守按钮的冷却；上一轮搜索未返回时不会重叠搜索。每次仍沿用当前搜索和过滤条件，手动取消的跳过名单不会因刷新清空。手动刷新后，下一次自动刷新也会延后 7 秒。
- 遵守游戏的申请上限，等待服务器确认上一项操作后补申。
- 每个申请从提交时分别计时。达到最大等待时间后自动撤销、加入本轮黑名单，并等待取消确认后补申。刷新、更换队长或结果 ID 变化不会重置倒计时；有队伍 GUID 时黑名单也会跟随同一队伍。游戏自己已结束的超时申请同样会被跳过。
- 搜索、战斗或收到邀请期间仍按实际时间计时，在恢复允许操作后处理到期申请；已经收到邀请的申请不会因到期而被撤销。停止自动申请时保留申请，再开启仍保留其原截止时间；新填写的等待时间只用于之后新提交的申请。
- 本功能提交的申请若职责已满、队伍满员或下架，会自动撤销并补申其他队伍。开启前已有的手动申请保留，仍占用游戏的申请名额。
- 搜索期间保留申请跟踪；搜索完成后优先使用队伍 GUID 识别同一队伍，恢复变化后的结果 ID。队长更换或队长名字暂缺不会直接丢掉仍在等待的申请；没有 GUID 时使用队长和地下城活动作为恢复依据。
- 原有每行的取消按钮继续可用。运行期间手动取消的队伍会跳过；通过队长和地下城活动识别，刷新后结果 ID 改变也不会重申。同一队长的同一地下城活动在本次运行中最多申请一次。
- 被拒绝或超时的队伍也不会反复申请。停止后重新开启会清空跳过名单，并继续跟踪此前由本功能提交、仍在等待的申请。
- 收到任何组队邀请时暂停，等待玩家处理。接受邀请、入队、切换专精、离开地下城分类或关闭查找页面时停止。
- 战斗期间、正在搜索、正在编辑搜索条件或正在手动填写申请时暂停。停止功能保留已提交的申请，玩家仍可手动取消。

更新补丁后执行 `/reload`，手动取消旧版本遗留的申请，再重新开启自动申请测试。申请跟踪仅存在于本次界面运行中，重载前的申请不会被新版自动接管。

仅使用普通游戏插件接口，不模拟按键，不绕过受保护操作。如果客户端阻止自动申请或自动刷新，或 10 秒内没有确认操作，会停止并提示手动操作。自动刷新失败或无响应时会恢复刷新按钮和搜索遮罩，方便手动继续。

## 验证

开发期间已通过 69 个 Lua 5.1 模拟场景，包含按钮悬停提示、默认 5 分钟、自定义等待时间、输入校验、每队独立截止时间、超时黑名单与刷新和邀请保护。测试脚本仅在本地保留，不随仓库发布。

模拟验证不能确认实际客户端的受保护接口限制、界面显示或服务器事件时序，这些需要在游戏内验证。
