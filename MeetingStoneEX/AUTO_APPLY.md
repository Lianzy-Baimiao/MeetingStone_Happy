# 自动申请地下城队伍

执行 `/reload` 后，在集合石「查找活动」中先选择地下城并设置搜索、过滤条件，再点击刷新按钮左侧的「自动申请」。先在备注提示中选择「带备注开始」「无备注开始」或「取消」，确认后才启动。按钮变成「停止申请」表示正在运行；鼠标悬停可查看当前状态。

按钮使用与刷新按钮相同的模板和字体，两个锚点都紧贴刷新按钮左侧（与右侧筛选按钮一样无间隙；装美化插件时由皮肤统一整行间距），因此高度与刷新按钮一致，刷新按钮被 EX 或美化插件移动时随之移动；装 ElvUI（WindTools）或 NDui（NDui_Plus）时，集合石自带的皮肤或这两个插件自己的集合石皮肤把它美化得与刷新按钮一样；不占用底部的职责和快速筛选栏。经典 UI 版的搜索行整体右移 40 像素，「双击加入」「自动进组」的文字会伸到按钮下方，此时打开查找页会把搜索框收窄到刚好让开（最小 160），文字变短时再放宽，最宽不超过集合石原本设置的 220；每次打开查找页都会重新计算，关闭后集合石照常还原搜索框。

备注窗口中可设置「最大等待时间」，输入 1–300 的整数秒，默认 300 秒（5 分钟）。例如填 `60`，表示每个自动提交的申请最多等待 1 分钟；带备注和无备注开始都会使用这一设置。

备注窗口可按住空白处拖动，松开后本次登录内再次打开仍在拖动后的位置（不写入存档，/reload 后回到默认位置；拖动由游戏引擎完成，不增加每帧开销）。「不需要备注可直接选择「无备注开始」」下方提示可在搜索框输入 10-12 这样的查询语句，筛选对应层数的队伍。

- 识别当前专精的坦克、治疗或输出职责，按五人队伍的 1 坦克、1 治疗、3 输出判断空位。
- 开始前复用游戏原有申请备注输入框（原有 63 字符限制），填写一次后本次申请沿用该备注。「无备注开始」会清空旧备注；「取消」、关闭弹窗或按 Esc 都不会启动。不会在自动刷新或补申时重复提示。
- 备注不自动保存到下次登录；再次开启时可以复用游戏输入框仍保留的文字。如果运行期间通过手动申请等方式修改了备注，自动申请会停止并提示重新确认，避免发送不同的内容。
- 使用当前完整过滤列表（包括滚动区域之外的行），按现有成员人数从多到少逐个申请。同人数按结果 ID 排序。
- 开启后约 7 秒自动调用原有刷新按钮的处理逻辑，并遵守按钮的冷却；后续从上一轮搜索返回时重新计时，约 7 秒后再次刷新，避免慢搜索连续触发刷新而无法申请。上一轮搜索未返回时不会重叠搜索。每次仍沿用当前搜索和过滤条件，手动取消的跳过名单不会因刷新清空。手动搜索返回或搜索失败后也等待约 7 秒再自动刷新。
- 遵守游戏的申请上限，等待服务器确认上一项操作后补申。
- 每个申请从提交时分别计时。达到最大等待时间后自动撤销、加入本轮黑名单，并等待取消确认后补申。刷新、更换队长或结果 ID 变化不会重置倒计时；有队伍 GUID 时黑名单也会跟随同一队伍。游戏自己已结束的超时申请同样会被跳过。
- 搜索、战斗、收到邀请、编辑搜索条件或打开手动申请窗口期间仍按实际时间计时，但不自动提交或撤销申请，在恢复允许操作后处理到期申请；已经收到邀请的申请不会因到期而被撤销。停止自动申请时保留申请，再开启仍保留其原截止时间；新填写的等待时间只用于之后新提交的申请。
- 本功能提交的申请若职责已满、队伍满员或下架，会自动撤销并补申其他队伍。开启前已有的手动申请保留，仍占用游戏的申请名额。
- 搜索期间保留申请跟踪；搜索完成后优先使用队伍 GUID 识别同一队伍，恢复变化后的结果 ID。队长更换或队长名字暂缺不会直接丢掉仍在等待的申请；没有 GUID 时使用队长和地下城活动作为恢复依据。
- 原有每行的取消按钮继续可用。运行期间手动取消的队伍会跳过；通过队长和地下城活动识别，刷新后结果 ID 改变也不会重申。同一队长的同一地下城活动在本次运行中最多申请一次。
- 被拒绝或超时的队伍也不会反复申请。停止后重新开启会清空跳过名单，并继续跟踪此前由本功能提交、仍在等待的申请。停止期间仍清理手动取消、被拒绝或已结束的申请记录；之后手动重新申请同一队伍，不会被旧截止时间接管或撤销。
- 收到集合石申请邀请或普通玩家直接组队邀请时暂停，等待玩家处理。拒绝普通邀请或收到邀请取消事件后恢复；接受邀请、入队、切换专精、离开地下城分类或关闭查找页面时停止。
- 战斗期间、正在搜索、正在编辑搜索条件或正在手动填写申请时暂停。停止功能保留已提交的申请，玩家仍可手动取消。

更新补丁后执行 `/reload`，手动取消旧版本遗留的申请，再重新开启自动申请测试。申请跟踪仅存在于本次界面运行中，重载前的申请不会被新版自动接管。

仅使用普通游戏插件接口，不模拟按键，不绕过受保护操作。如果客户端阻止自动申请或自动刷新，或 10 秒内没有确认操作，会停止并提示手动操作。自动刷新失败或无响应时会恢复刷新按钮和搜索遮罩，方便手动继续。

## 验证

本地修复版需通过 110 个 Lua 5.1 模拟场景。保留原有 69 项场景，其中一项刷新时序断言更新为“搜索返回后等待 7 秒”；新增 31 项回归场景，覆盖 7–9 秒慢搜索、失败重试、停止期间的申请清理、结果 ID 变化、普通邀请的接受与拒绝，以及编辑期间暂停撤销；另有 9 项覆盖按钮模板、宽度与双锚点、开关文字、每秒驱动只在运行时启用，以及经典版搜索框避让（收窄、最小宽度、放宽、不处理的情况）；另有 1 项覆盖备注窗口拖动（无每帧脚本、不写布局存档、重新打开回到拖动位置）与 10-12 查询提示。

回归脚本位于 `tests/test_auto_apply.py`，需要 Python 和 `lupa`，不会由插件 TOC 加载，也不部署到游戏目录：

```powershell
python -X utf8 MeetingStoneEX/tests/test_auto_apply.py
```

模拟验证不能确认实际客户端的受保护接口限制、界面显示或服务器事件时序，这些需要在游戏内验证。

## 游戏内测试建议

1. 手动取消不再需要的旧申请，执行 `/reload`，打开「查找活动」，选择地下城和过滤条件。点击「自动申请」，先用 30 秒最大等待时间测试。
2. 分别测试带备注和无备注开始，确认会按当前职责逐个申请，且不会超过游戏申请上限。
3. 自动申请后，让搜索框保持输入焦点直到超过 30 秒：期间不应自动撤销，离开输入框后才处理超时。手动申请窗口同样应暂停；如果修改了备注，按原有规则停止并要求重新确认。
4. 自动提交后停止，手动取消，再手动申请同一队伍；重新开启自动申请后，这条手动申请不应被原来的截止时间撤销。
5. 让好友发普通组队邀请：等待处理时不应继续申请、刷新或撤销；拒绝后恢复，接受后停止。
6. 搜索较慢时，确认结果返回后仍会申请，并等待约 7 秒再刷新。若提示受保护接口被阻止，停止测试自动功能，记录提示或报错；不要尝试绕过客户端限制。
7. 分别在新 UI 版、经典 UI 版（MeetingStone 与 MeetingStoneEX 整套替换），以及装与不装美化插件时查看按钮：与刷新按钮等高、位于其左侧，不遮挡「双击加入」「自动进组」；经典版搜索框会略微变窄。
8. 拖动备注窗口，取消后再点「自动申请」：窗口应出现在拖动后的位置；/reload 后回到默认位置。
9. 装 ElvUI + WindTools 或 NDui + NDui_Plus 时：分别在「使用Wind皮肤」「使用NDui皮肤增强」开、关两种情况下，看自动申请按钮与刷新按钮样式是否一致。
